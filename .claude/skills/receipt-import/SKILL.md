# レシート写真の取り込み

添付されたレシート写真を読み取り、`receipt2yayoi/` の台帳に追加して、
弥生会計にインポートできるCSVを作り直す。

このスキルの利用者は経理やプログラミングの専門家ではない。
専門用語を並べず、結果を日本語で短く報告すること。

## 手順

### 0. 誰の分か確定させる

**英之と祐子は申告が別で、台帳も完全に分かれている。**

- `英之` → `--person 英之`（台帳 `ledger/hideyuki.json` / CSV `out/hideyuki/`）
- `祐子` → `--person 祐子`（台帳 `ledger/yuko.json` / CSV `out/yuko/`）

利用者は使う前に誰の分か宣言する運用になっている。会話のどこかで
「英之の分」「祐子用」と言われていれば、**その会話の間はその人のまま**
扱ってよい。毎回聞き直さない。

宣言がまだない、または切り替わったか判断がつかないときは、
**写真を読む前に必ず聞く**:

> このレシートは英之さんと祐子さん、どちらの分ですか？

推測で登録してはいけない。混ざると申告をやり直すことになり、
一度入れた経費がどちらのものか後から見分けられない。
一言聞くコストのほうが圧倒的に安い。

複数枚まとめて送られた場合も、全部同じ人の分とは限らない。
違う人の分が混ざっていそうな気配があれば確認する。

### 1. 写真・PDFを読み取る

添付ファイルはすでに見えている。**APIに送り直さない**（二重に費用がかかる）。
自分で読み取り、次のJSONを組み立てる。

**PDFが直接読めないとき**（`pdftoppm is not installed` など）は、
画像に変換してから見る:

```bash
python3 -c "import pymupdf; pymupdf.open('<PDF>')[0].get_pixmap(dpi=200).save('/tmp/p.png')"
```

`pypdf` のテキスト抽出は、この手の領収書PDFでは文字化けして使えない。
必ず画像にして目で読むこと。

```json
{
  "issue_date": "2026-04-05",
  "shop": "スターバックス 渋谷店",
  "total": "1100",
  "payment": "クレジットカード",
  "invoice_number": "T9010001000001",
  "lines": [{"name": "ドリップコーヒー", "amount": "550", "tax_rate": 10}],
  "warnings": []
}
```

読み取りの決まり:

- `total` は税込合計。カンマや「¥」を除いた半角数字のみ。
- `issue_date` は `YYYY-MM-DD`。和暦は西暦に直す。**年が印字されていなければ `null`**。
- `tax_rate` は 8 か 10。※印・「軽」マーク・持ち帰りの飲食料品は 8。
- `invoice_number` はTで始まる13桁。なければ `null`。
- `payment` は `現金` / `クレジットカード` / `電子マネー` / `QRコード決済` / `デビット` / `不明`。
  事業用の口座・カードと**分かっているときだけ** `事業用口座` / `事業用カード` にする。
- **クレジットカード番号は書き写さない。** 台帳にもCSVにも残さない。
- `lines` は読めた範囲でよい。全部は要らない。税率が混ざっている場合だけは必ず分ける。
- **読めないものを推測しない。** 迷ったら `null` にして `warnings` に日本語で理由を書く。
  推測した数字が申告書に載るほうが、要確認フラグが1つ増えるよりずっと悪い。

### 2. 台帳に記録する

```bash
cd receipt2yayoi
echo '<上で作ったJSON>' | PYTHONPATH=. python3 -m receipt2yayoi.cli record \
  --person <英之 or 祐子> --image "<添付画像のパス>" --year <その年>
```

`--person` は必須。省くとコマンドが止まる（既定値を持たせていないのは、
うっかり片方に寄せてしまう事故を防ぐため）。`--file` はPDFでもよい。

### まとめて送られたとき

**1枚ずつ報告しない。1枚ずつコミットしない。** 登録そのものは1秒ほどだが、
毎回コミットとpushを挟むと待ち時間が枚数分かさむ。

1. 全部読み取って、`record` を**続けて実行**する（間に報告を挟まない）
2. **最後に1回だけ**コミットして push する
3. 報告も最後に1回、表にまとめて出す:

> ✅ **英之** 5枚を登録しました。
>
> | 日付 | 店名 | 金額 | 科目 |
> |---|---|---|---|
> | 9/18 | 東海旅客鉄道 | 9,300円 | 旅費交通費 |
> | 9/20 | ファミリーマート | 918円 | 消耗品費 |
>
> 今年は合計 23枚・48,300円です。⚠ 2枚は要確認です（下記）。

確認が必要なものだけ、そのあとにまとめて聞く。

写真が複数枚あるときは1枚ずつ繰り返す。
同じファイルを再度送られた場合は自動でスキップされる（二重計上しない）。

### 2-b. 同じ支払いの証憑が2つ来たら

「ご利用票」を登録したあとに正式な領収書PDFが来る、といったことが起きる。
**ファイルが違えば別物として登録されるので、自動では防げない。**
同じ日付・同じ金額・同じ内容に気づいたら、古いほうを取り消してから入れ直す:

```bash
PYTHONPATH=. python3 -m receipt2yayoi.cli remove --person <誰> --match "<店名や金額>" --year <年>
```

残すのはインボイス登録番号が入っているほう（＝正式な領収書）。
取り消したことは報告に一言入れる。黙って消さない。

## 勘定科目の目安

`rules.py` が自動で当てるが、判断に迷ったときの基準はこれ。

| 内容 | 科目 |
|---|---|
| 新幹線・電車・バス・タクシー・駐車場・高速代 | 旅費交通費 |
| 書籍・雑誌・新聞 | 新聞図書費 |
| 文具・小物・ソフト（10万円未満） | 消耗品費 |
| 打合せの飲食（少人数・会議目的） | 会議費 |
| 接待・贈答・懇親 | 接待交際費 |
| 電話・郵送・ネット | 通信費 |
| セミナー受講料・会場費 | 研修費 または 雑費（迷えば聞く） |

迷うものは候補を添えて確認する。勝手に決めきらない。

## 貸方と税区分（コードが自動で付けるが、聞かれたら説明できるように）

**貸方の既定は `事業主借`。** 個人のカード・現金で立て替えて払っているため。
事業用の口座・カードと分かるときだけ `普通預金` / `未払金` になる。

**税区分は税込記帳なので「内」（内税）。**

| | 10% | 8%軽減 |
|---|---|---|
| インボイス登録番号あり | `課対仕入内10%` | `課対仕入内軽減8%` |
| なし・2026/9/30まで | `課対仕入内10%区80%` | `課対仕入内軽減8%区80%` |
| なし・2026/10/1以降 | `課対仕入内10%区70%` | `課対仕入内軽減8%区70%` |

経過措置の控除率は **2026/10/1に80%→70%へ下がる**。取引日で自動的に切り替わる。

税額 = 税込金額 × 税率/(100+税率) の切り捨て（例: 8,570円・10% → 779円）。
貸方の税区分は `対象外`、税金額は 0。

> 弥生側にこの税区分名が無いとインポートエラーになる。そのときは弥生の
> 税区分一覧の表記に合わせて `rules.py` の `tax_category` を直す。

## よく出てくる証憑の扱い（決まりごと）

ここに書いてあるものは、もう聞かずにこのとおり処理してよい。

### 新幹線（EX予約・スマートEX）

出張で毎回出てくる。証憑が2種類あり、**同じ1回の乗車で両方そろうことがある**。

| 証憑 | 見分け方 | 扱い |
|---|---|---|
| **EXご利用票（座席のご案内）** | 青い小さな券。「きっぷではありません」と印字 | 登録はするが要確認。インボイス番号がないので経過措置（区分80） |
| **領収書PDF** | A4。「領収書 RECEIPT」、登録番号 T3180001031569 | **こちらが正。** 満額控除になる |

- 勘定科目は **旅費交通費**。`rules.py` に「東海旅客鉄道」「スマートEX」「こだま」等を
  登録済みなので自動で当たる。
- 計上日は**領収書の購入日**（カード決済日）。乗車日が違う場合は摘要に書く。
  年をまたぐ購入（12月購入・1月乗車）だけは利用者に確認する。
- **両方そろったら、ご利用票のほうを `remove` して領収書PDFに差し替える。**
  黙って消さず、差し替えたことを報告に書く。

#### 同じ日・同じ金額が2枚あっても、重複とは限らない

往復は別々の予約として発券される。**予約番号（「予2081」「予2082」）または
発行番号が違えば、別の支払い。** 2件として登録してよい。

重複を疑うのは、予約番号まで一致しているときだけ。

### 3. 保存する

台帳 `receipt2yayoi/ledger/<誰>.json` と `receipt2yayoi/out/<誰>/` の
CSVをコミットして push する。コミットメッセージは日本語で、
「レシート追加: 3/5 スターバックス 1,100円」のように中身が分かる形にする。

### 4. CSVを渡す

**表を見せて終わりにしない。** 弥生に取り込むのはファイルなので、
`SendUserFile`（`display: "attach"`）で `out/<誰>/yayoi_import_<年>.csv` を渡す。

確認用の `review_<年>.csv` は、要確認の行があるときだけ一緒に渡す。

### 5. 報告する

1行で結果を伝える。例:

> ✅ **英之** 4/5 スターバックス 渋谷店 1,100円 を「会議費」で登録しました。
> 英之さんは今年これで 23枚・48,300円です。

**誰の台帳に入れたかを必ず文頭に出す。** 取り違えにその場で気づけるようにする。

以下に当てはまるときだけ、加えてひとこと確認する:

- 勘定科目が `雑費` になった → どの科目が適切か尋ねる
- `warnings` が付いた／日付が読めなかった → 何が読めなかったかを伝えて聞く
- 金額が1万円を超える → 事業用かプライベートかを確認する

それ以外のときは余計な説明を足さない。毎回長い解説が出るとレシート登録が面倒になる。

## 台帳について聞かれたら

```bash
cd receipt2yayoi && PYTHONPATH=. python3 -m receipt2yayoi.cli list --person <誰> --year <年>
```

## パソコンにたまった分をまとめて処理したいと言われたら

チャットに何十枚も送るより、フォルダごと `add` に渡すほうが速い。
読み取りは並列で走る（既定4件同時）:

```bash
cd receipt2yayoi && PYTHONPATH=. python3 -m receipt2yayoi.cli add <フォルダ> \
  --person <誰> --year <年> --workers 8
```

これには `ANTHROPIC_API_KEY` の設定が要る。未設定なら設定を案内する。

「今年いくら？」「何枚入ってる？」にはこれで答える。
誰の話か曖昧なら、両方出すのではなく先に聞く。
「2人分まとめて」と明示されたときだけ、2回実行して並べて見せる。

## 弥生に取り込む段になったら

- 取り込むファイルは `receipt2yayoi/out/<誰>/yayoi_import_<年>.csv`（Shift_JIS）
- その前に `out/<誰>/review_<年>.csv` をExcelで開いて、**「要確認」の行を直してもらう**
- **英之の申告には英之のCSVだけ**を使う。取り違えないようファイル名を読み上げて渡す
- 弥生会計デスクトップ: ファイル → インポート
- やよいの青色申告オンライン: スマート取引取込 → ファイル取込

勘定科目の最終判断は事業主本人のもの。こちらで確定させない。

## 新しい決まりごとを覚えてほしい、と言われたら

「スキルに登録して」「次からこうして」と言われたら、**この SKILL.md に書き足す**。
会話の中だけで覚えても次のセッションには残らない。

- 勘定科目の判定に関わるものは `rules.py` の `KEYWORD_RULES` にも足す
  （ここに入れば自動で当たるので、要確認が減る）
- 判断の仕方（どちらを正とするか、何を重複とみなすか）は上の
  「よく出てくる証憑の扱い」に追記する
- 足したらテストを走らせ、コミットして push する

## よく使う科目を覚えさせたい、と言われたら

`receipt2yayoi/receipt2yayoi/rules.py` の `KEYWORD_RULES` に店名を足す。
ルールは2人で共有している（「コンビニは消耗品費」はどちらでも同じ）。
片方だけ科目を変えたい場合は、その旨を確認してから個別対応を考える。
ここが充実するほど「要確認」が減る。追加したらテストを走らせる:

```bash
cd receipt2yayoi && PYTHONPATH=. python3 -m pytest tests -q
```
